# XYO Coff to Def — Documentation

`xyo-coff-to-def` reads **COFF object files (`.obj`)** produced by the
Microsoft C/C++ compiler (or a compatible one, like `clang-cl`) and writes a
**module definition file (`.def`)** that lists every symbol those objects
define, ready for `link.exe /DLL /DEF:file.def`.

```
xyo-coff-to-def --out zlib.def adler32.obj compress.obj deflate.obj ...
link /DLL /DEF:zlib.def /OUT:zlib.dll adler32.obj compress.obj deflate.obj ...
```

## Why it exists

A static library or a set of objects written without
`__declspec(dllexport)` can still be turned into a DLL: the linker exports
whatever the `.def` file lists. Writing that list by hand for a C++ library
means copying hundreds of decorated names (`?cppFn@NS@@YAHH@Z`).
`xyo-coff-to-def` reads them from the objects instead.

| Problem | What `xyo-coff-to-def` does |
|---------|-----------------------------|
| A library has no `dllexport` markings | exports every external symbol the objects define |
| C++ names are decorated | copies the decorated names as they are |
| i386 C names have a leading `_` the DEF file must not repeat | `_name` (cdecl) is written as `name`; `_name@8` (stdcall), `@name@8` (fastcall) stay decorated |
| Data needs `DATA` in a DEF file | variables (and C common variables, `int x;`) are written as `name DATA` |
| The compiler adds internal symbols (floating point constants, vftables, RTTI, throw info) | those are filtered out |
| Objects come from a big project | many objects at once, `@list.txt` response files, `/bigobj` objects |

Its main user is [lib-to-dll](https://github.com/g-stefan/lib-to-dll),
which extracts the objects of a static `.lib`, calls
`xyo-coff-to-def --out name.dll.def --mode WIN32|WIN64 ...` and links them
into a DLL.

## Concepts at a glance

| Need | Command line |
|------|--------------|
| DEF from objects | `xyo-coff-to-def --out my.def a.obj b.obj` |
| Many objects | `xyo-coff-to-def --out my.def @objects.txt` (one file name per line) |
| See what the objects define | `xyo-coff-to-def --show a.obj` |
| Force the naming rules | `--mode WIN32` (i386 decoration) or `--mode WIN64` (names as they are); default `AUTO` picks by the object's machine |
| Check it worked | exit code `0`; any unreadable or invalid input gives exit code `1` and no `.def` |
